# 会话架构与 Token 预算

项目只保留一套会话流程。回退使用已验收的镜像与前端，不在运行代码中维护旧会话执行器。

## 职责

| 组件 | 职责 |
| --- | --- |
| `engine` | 接收、去重、合批、概率筛选与调度 |
| `conversation` | 轻量参与判定、角色回复、工具调用与最终回复检查 |
| `context` / `working_context` | 稳定前缀、近期窗口、资料预算与历史补读引用 |
| `tool_loop` | 两种模型协议的有界工具循环与结构化结果裁剪 |
| `reply_review` / `delivery` | 相关插话复核、限频、分段、去重与未知结果处理 |
| `participation_memory` / `memory` | 参与会话的整理时机、明确记忆优先与持久任务 |
| `knowledge` / `memory_semantics` / `memory_sources` | 事实来源、身份、纠正与群表达学习 |
| `attachments` / `image_turn` | 图片编号、原图与局部读取、参考图和图片预算 |
| `image_search` / `image_evidence` | 单次搜图、来源、缓存与后续证据复用 |
| `forwards` / `scheduler` | 合并转发读取、定时查询生成与直接提醒 |

## 消息与发送

同群同成员的重复文字在 60 秒内只受理第一条；空白及仅 @ 的消息按输入过滤规则处理。明确 @、昵称唤醒、回复机器人和私聊进入完整回复流程。普通群聊先按本群概率抽样，默认 1%；命中的文字进入轻量判定，带当前或明确引用图片的消息直接进入主模型。未命中不调用模型。

回复流程一次生成参与决策和正文，模型仍可沉默。每轮最多四次主模型调用、六次工具调用；历史查询与图片补读另受三次上限约束。原生思考块按协议保留，不作为公开回复。

能力询问使用当前工具状态，并在获准时复用 `capabilities` 核实机器人 QQ 身份。明确质疑旧操作时，服务先通过原有 `history_search` 权限查询操作记录，再生成角色回复；预读计入现有工具与历史额度，不增加执行授权。`history_search` 的可选 `operation`、`target_user_id` 按工具及目标筛选，`history_read` 可返回与原消息绑定的操作回执。只读取同群、同角色、未遗忘且仍可见的来源，区分接口接受、独立回读、拒绝与结果未知；日期按操作时间核对，昵称重名不能猜测对象。发送前对能力否认、本人范围指代和历史结果矛盾作纠正，并复核证据与配置是否仍有效。助手语气保留，询问能力或旧事不视为新操作请求。

发送前与分段间共用请求关联检查：无关群聊和其他成员的独立图片不打断答案；原请求者补充、相关引用和纠正进入有界复核。复核携带真实 QQ、消息 ID、引用及 @ 关系，只判断是否发送已有内容，不重新生成正文或搜图。

每条实际发送计入每群每分钟二十条上限。明确请求不因临时满额直接变成沉默，最多等待 65 秒；等待后仍检查暂停、遗忘、权限和插话。正文优先，可选表情在额度不足时省略并记录原因。只登记确认发出的内容，未知结果不自动重试。文字与表情分别发送，保留原始文件和动画，并使用 QQ 自定义表情类型。

明确总结长转发时，超过单次图片上限的图集交给 `forward_batches` 按顺序分批读取。默认单次最多 12 张、视觉预算 49152；单份请求最多处理 128 张，批读总耗时上限 240 秒，最终回复时效放宽到 300 秒。每批使用同一聊天模型但不开工具，仅保留来源绑定的逐图观察供最终角色回复；不写长期记忆，不把引用身份当权限。批次间释放像素，权限或来源变化立即停止，部分失败明确给出已读／未读数量。三项文字上下文预算独立控制。

网页抓取仍交给已配置的供应商。`web_address` 对本地 Fake-IP 解析或解析失败采用固定公网地址的 TLS 验证 DoH 复核，检查 A、AAAA；实际私网答案及字面私网地址不走放行。QQ 图片下载继续使用原有严格地址检查。该复核不关闭 TLS、不使用用户提供的 DNS 地址。

## 上下文与历史

固定规则、角色、工具、会话标识及稳定历史在前；时间、当前消息、权限、成员资料、引用和本轮召回在尾部。历史不带动态 current 标记。工作上下文只保存消息引用并按接收顺序追加，超预算后逐条移出最旧的非受保护消息。

| 设置 | 默认值 |
| --- | ---: |
| 旁听判定消息数 / 软预算 | 80 / 32,000 |
| 工作上下文初始消息数 / 上限 | 40 / 80 |
| 工作上下文软预算 | 32,000 |
| 输入硬预算 | 256,000，另受模型容量和输出预留限制 |
| 图片数 / 视觉预留 / 请求体 | 6 / 24,576 / 16 MiB |

预算是保守估算，不等于供应商计费 token。当前问题、引用、未完成工具链和必要跟聊资料受保护，普通回复优先保留最近六条原文，仍不得超过硬预算。工具结果先裁剪结构，再序列化为完整 JSON；图片 Base64 不作为文字 token 计算。

移出输入的原文仍按保留期保存，可通过 history_search/history_read 按需补查。群、角色、模型和提示词版本隔离；遗忘、停止记忆、重置和配置变化使相应快照失效。旧压缩执行器和滚动摘要生成已退役；历史记录保留，遗忘仍清理相关旧派生资料。

## 事实与群表达

成功发送聊天回复后记录本轮实际使用的来源。机器人停止参与十分钟后封存；持续参与最长两小时封存一次。后续群友发言不延后时间，也不进入已封存范围。

后台分批整理未处理来源，成功后标记，失败有限重试。长期沉默不建立全群积压任务，重新开口也不补扫全群历史；明确记忆和纠正优先。稳定任务编号支持重启恢复，旧全群积压记录作为历史保存，不进入当前调度。

## 图片、搜图与转发

当前和明确引用的图片随主模型输入。历史附件具有稳定编号，image_read 将真实图片送入下一次主调用；纯文字模型仍使用图片描述降级路径。角色设定图只由后台上传。

聊天图片保留原文件供小字核对，预览最长边 1600，截图尽量保留 PNG。每轮至多补看一次局部，共用图片与工具预算。保留现存图片缓存的读取能力；过期、不可读和原图缺失状态必须明确，不能把缺失像素当成已识别文字。

QQ 原图下载与解码上限为 32 MiB、2000 万像素；模型预览仍限 8 MiB、最长边 1600，并继续受整轮图片数量和传输预算约束。按响应头和实际流量分别限量，解码串行化；已保存原图按需从文件读取，不让一轮的所有原始字节常驻内存。角色参考图上传及表情收藏保留各自原有上限。

`runtime.social_tone` 仅提供通用交流指导；具体性格、语气和外观由当前角色配置决定，未配置的身份与关系不补造。引用和图片内容先核实，尊重明确停止要求；角色设定不改变权限和执行证据。

SearchRequests 核对明确搜索请求是否由同一请求者的工具调用完成；漏搜最多在原工具循环内纠正一次。image_search 每轮最多一次 SerpApi / Google Lens 搜索，不另取 AI 概览，不自动重试；免费额度不足或不能确认时停止。结果缓存按群、角色、记忆版本和密钥版本隔离，来源关联原图并可在后续补读中复用。

forward_read 读取有权限的合并转发，最多三层，正文分页，内部图片共用预算。仅总结转发时不混入周围群聊；读取失败不能以无关聊天替代。更多图片、表情和工具规则见 [功能说明](features.md)。

## 权限、用量与验证

工具定义保持稳定，运行时核对启用状态、真实请求者授权及 QQ 实际权限；网络等待后重查来源、权限和遗忘状态。撤回本人消息使用独立授权，角色关系与引用内容不授予权限。

保留 chat / decision / memory 模型路由。阶段、调用 ID、追踪和真实缓存字段关联到用量；未返回的数据标为未知，不伪造历史统计。当前提示词沿用编辑、发布、版本恢复和请求内快照，已发布的有效模板与角色卡保持原样。

后端回归按功能组织，浏览器验证统一使用 npm --prefix frontend run test:ui。日常测试使用模拟模型、Lens 和 OneBot，不产生真实费用或 QQ 消息。发布与镜像回退见 [运维说明](operations.md)。
